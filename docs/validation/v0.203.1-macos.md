# v0.203.1 — macOS validation

Validated on 2026-09-07 on a physical Apple M1 MacBook Air running macOS 26.2 (25C56), ARM64.

## Reproduced defects

- v0.203.0 passed its published SHA-256 and `codesign --verify --deep --strict`, but DYLD rejected the Electron framework at launch. The ad-hoc main executable and helpers enabled hardened runtime without the required library-validation exception.
- After correcting the local signature, opening HyperFrames Preview raised an uncaught `setTypeOfService EINVAL` from Electron's bundled fetch/undici readiness request.

## Fixes and automated checks

- Ad-hoc signing supplies per-process entitlements that preserve the defaults of Forge's actual osx-sign dependency and add `com.apple.security.cs.disable-library-validation`. A configured Developer ID retains the normal signing path. Hardened runtime and system Gatekeeper remain enabled.
- Local preview readiness uses a bounded `node:http` loopback request instead of bundled fetch. A stalled request is destroyed after one second; errors resolve as not ready.
- Ten regression tests passed: signing selection and actual entitlement contents, real HTTP readiness including refused/hung connections and no fetch dependency, and the existing concurrent asset-library reload tests.
- Desktop TypeScript/main/preload/native build and web TypeScript/Vite build passed.
- `scripts/verify-macos-signing.mjs` correctly rejected the original v0.203.0 app and accepted the new package. It checks every Electron app/helper for hardened runtime and the ad-hoc exception, verifies the bundle, and actually starts the packaged Electron executable.

## Installed-package validation

Built ARM64 DMG and ZIP locally with Forge. Mounted the generated DMG read-only and installed its app into Applications; no post-install re-signing was performed on v0.203.1.

- Package version and bundled CLI: `0.203.1`; CLI ran with `PATH=/usr/bin:/bin` (no system Node).
- Native app opened, reloaded the saved test project, and retained the linked timeline element.
- HyperFrames Preview loaded its local player and composition; Play advanced from 0:00 to 0:02 without the previous exception.
- A new render completed using the bundled HyperFrames 0.8.30, browser and FFmpeg.
- FFprobe confirmed H.264, 640×360, 30 fps, 60 frames, duration 2.000000 seconds.
- Re-render retained the same logical generated asset and timeline element; no duplicate clip was created.

## Limits

This physical-Mac check covers ARM64. Intel and Windows must pass their native release workflow jobs before GitHub publishes the complete installer set. The builds remain ad-hoc signed, without Apple Developer ID/notarization. These targeted checks are not an exhaustive editor feature audit.
